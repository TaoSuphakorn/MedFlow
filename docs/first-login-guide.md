# Interactive first-login tutorial

On first entry, an account sees a spotlight around a real control with an adjacent teaching panel. The five steps cover opening Patients, entering a search, opening a patient, reading history/allergies and understanding the SOAP field/role permissions. On phones the first step initially points to the navigation opener, then Patients inside the drawer. Thai and English can be switched inside the panel.

The tutorial waits for actual Patients and patient-open clicks. Search requires non-whitespace text before Next; a search with no matches offers Previous so the user can change it. History and the final explanation use Next/Finish. Skip, Close, Escape and finishing remember the tutorial for the account. The shaded background blocks unrelated pointer actions. Nothing generates AI content, saves a note or confirms clinical content automatically.

Help & demo guide → Restart walkthrough opens it again. If a patient is already open, replay begins at history rather than navigating away and losing unsaved text. If Visit history is selected, the final step points to the real Clinical documentation tab and waits for it to reveal Subjective. Administrators receive read-only role guidance. After replay, focus returns to Help on desktop or the phone navigation opener; after initial completion it returns to the main workspace.

The existing `Users.OnboardingSeenAt` UTC preference and authenticated, CSRF-protected `POST /api/auth/onboarding` are unchanged. Skip/finish mark only the current account and preserve the first timestamp. The preference follows the account across browsers/devices. Accounts that already dismissed the earlier introduction can replay the new tutorial from Help; this update does not reset their preference. Skip and finish share a seen flag rather than completion analytics.

Transient save failures leave the guide open with an error and retry controls. An expired session returns to login. Clearing browser storage does not reset the server preference. Resetting patient demo records also leaves account preferences intact.

`use-tour-target.ts` positions the spotlight and teaching panel around visible targets, follows scroll/resize/drawer transitions, and uses visual viewport size/offset events for the phone keyboard. The panel body scrolls while actions remain available. The explanatory Subjective step does not focus the textarea and summon a keyboard. Tab cycles between the highlighted control and tutorial buttons; Escape skips. Missing targets retain Skip and explanatory fallback text. No dependency or external service was added.

Dedicated browser tests cover real navigation/search/open interactions, empty-result recovery, persistence across browser contexts, role copy, unsaved-draft replay, history-tab recovery, phone/language behavior, focus and error handling. Keyboard geometry is tested with a simulated reduced visual viewport, not a physical iOS/Android keyboard. Existing clinical suites model returning users by overriding only the guide preference. All browser writes run in a disposable Docker project.
